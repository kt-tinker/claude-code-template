# セキュリティ

- 秘密情報（API キー、トークン、パスワード、接続文字列）をコード・ログ・テスト・コミットに含めない。環境変数から読む
- `.env` や `secrets/` は読まない。必要な変数名は `.env.example` で確認する
- 外部からの入力（リクエスト、クエリ、ヘッダー、ファイル、環境変数）はすべて検証してから使う
- SQL は ORM かパラメータ化クエリを使う。文字列連結でクエリを組み立てない
- HTML に動的な値を出すときはエスケープする。`dangerouslySetInnerHTML` / `innerHTML` は原則使わない
- シェルコマンドにユーザー入力を渡さない。どうしても必要なら引数配列で渡す
- 認証・認可のチェックをクライアント側だけで済ませない
- エラーメッセージに内部情報（スタックトレース、SQL、パス）を含めない
- 依存パッケージを追加・更新したら `npm audit` の結果を確認する
- セキュリティに関わる変更（認証、権限、暗号、入力検証）をしたら、作業の最後に security-auditor サブエージェントでレビューする
